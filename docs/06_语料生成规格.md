| 项 | 内容 |
|---|---|
| 版本 | v0.1 |
| 适用 | 项目 A |
| 里程碑 | **M1** |

## 1. 三条生成原则

| # | 原则 | 具体要求 |
|---|---|---|
| G1 | **像真的** | 结构、术语、单位、语气都要符合工业文档习惯；不是"示例文本 A/B/C" |
| G2 | **自洽** | 六类语料之间的数字必须互相对得上（见 §6）。语料内部矛盾会让评测失效 |
| G3 | **可溯源** | 每一条知识单元都有 `doc_id` + 位置（页/条款）+ ground truth，评测集从它派生 |

### 1.1 为什么先生成结构化源、再渲染

- **ground truth 必须独立于渲染格式**。源文件即答案表，评测集从它自动派生，避免"自己标自己"
- **一份源数据渲染多格式**：同一份手册同时产出 DOCX 与 PDF，验证两条解析路径
- **可 diff**：改一处不用重生成全部

| # | doc_id | 类型 | 权威级 | 渲染产物 | 规模 |
|---|---|---|---|---|---|
| 1 | `capability-matrix` | 能力矩阵 | manual | `tables/capability.xlsx` | 30 行 |

| 3 | `lead-time` | 交期表 | manual | `tables/leadtime.xlsx` | 10 行 |
| 4 | `manual-tempering` | 设备手册（清单式） | manual | `manuals/tempering.docx` + `.pdf` | 9 节 / 约 5 页 |
| 5 | `manual-iglazing` | 设备手册（条款式） | manual | `manuals/iglazing.pdf` | 6 节 / 约 5 页 |
| 6 | `manual-tempering-scan` | 扫描版节选（测 OCR） | manual | `manuals/tempering_scan.pdf` | 4 页，无文本层 |
| 7 | `std-summary` | 澳洲标准摘要 | **standard** | `standards/*.md` | 5 个标准 / 9 条 |
| 8 | `experience-fieldbook` | 客服战地手册 | **experience** | `experience/fieldbook.md` | 40 条 |
| 9 | `tickets-2025` | 历史工单 | **experience** | `tickets/tickets.jsonl` | 30 条 |

**合计约 130 条知识单元**（30 能力矩阵行 + 20 报价 + 10 交期 + 9 标准条 + 40 经验 + 30 工单 + 2 份手册）。

> 两份手册是**节选**，不是完整手册：够覆盖"文本型 PDF / 条款式 PDF / 扫描件 / DOCX 表格"四条解析路径即可。
> 实际 chunk 数量在 M1 入库后统计并回填。

### 2.1 为什么第 5 份手册风格不同

中德设备文档风格差异极大，且直接决定切分策略：

| 来源风格 | 特征 | 切分策略 |
|---|---|---|
| 清单式（第 4 份） | 参数表、编号列表、短句、警告框 | 按表格行 + 清单项切 |
| 条款式（第 5 份） | 长句、层级深（`4.2.1.3`）、冗长 | 按编号层级切，chunk 带完整路径 |

**这是"按文档来源路由切分策略"的验证载体**，不是凑数。

## 5. 各源文件的 schema

### 5.1 `manual_*.yaml`（设备手册）

```yaml
doc:
  doc_id: manual-tempering
  title: Tempering Furnace TF-2448 Operation Manual
  revision: C
  language: en-AU
  style: checklist          # checklist | clausal
sections:
  - number: "1"
    title: Safety
    paragraphs:
      - "Only trained operators may run the tempering cycle."
    warnings:
      - level: DANGER          # DANGER | WARNING | CAUTION | NOTE
        text: "Never open the furnace door while the quench section is pressurized."
    tables: []
  - number: "4"
    title: Operating Parameters
    tables:
      - caption: "Table 4-1 Recommended heating times by thickness"
        columns: ["Thickness (mm)", "Heating time (s/mm)", "Quench pressure (kPa)"]
        rows:
          - ["4", "38", "12"]
          - ["6", "42", "18"]
          - ["8", "46", "22"]
          - ["10", "50", "26"]
          - ["12", "55", "30"]
```

**约束**

| # | 约束 |
|---|---|
| M1 | `number` 形如 `"1"` / `"4.2"` / `"4.2.1"`；条款式手册可用三层 |
| M2 | 每个 `table` 必须有 `caption`，表格第一行必须是表头 |
| M3 | 表格行数与厚度枚举一致（见 §6.1），不得出现 7mm |
| M4 | 每份手册至少 2 个 `warnings`，级别分布覆盖 DANGER/WARNING/CAUTION |
| M5 | 清单式手册以 `paragraphs` + `tables` 为主；条款式以长 `paragraphs`（≥3 句）为主 |

### 5.2 `standards.yaml`（标准摘要）

```yaml
standards:
  - code: AS 1288
    title: Glass in buildings - Selection and installation
    edition: "2006 (incl. Amdt 1)"
    sheets:
      - topic: Safety glazing in doors and side panels
        section: "Section 5"          # 只写节标题，不编造条款号（见 §9）
        summary: >
          Glazing in doors, side panels and other human-impact locations must be
          safety glazing. Annealed glass is not acceptable in these locations.
        answer_en: >
          Glass in doors and side panels must be safety glass - toughened or
          laminated. Ordinary annealed glass is not permitted there.
        applies_to: [door, sidelight, shopfront]
  - code: AS/NZS 2208
    title: Safety glazing materials in buildings
    sheets:
      - topic: Marking of safety glazing
        section: "Section 2"
        summary: "Safety glazing must be permanently marked by the manufacturer."
        answer_en: "Safety glass must carry a permanent mark identifying the manufacturer and the standard."
        applies_to: [all]
```

**约束**

| # | 约束 |
|---|---|
| S1 | 只用真实存在的标准号与标题：`AS 1288`、`AS/NZS 2208`、`AS 4666`、`AS 1926.1`、`AS 3959` |
| S2 | **`section` 只写节标题或节号，不编造具体条款号**（如 `5.3.2`） |
| S3 | 每条必须有 `answer_en`（可直接对客户说的英文结论），与 `summary` 不同 |
| S4 | 只做摘要，不抄原文（版权） |
| S5 | 每条 `answer_en` 必须包含限定语，禁止出现"保证合规"类表述 |

### 5.3 `experience.yaml`（客服战地手册）

```yaml
entries:
  - entry_id: EXP-001
    topic: post-installation cracking
    question: Customer reports cracks two weeks after installation. Is it a defect?
    answer_en: >
      Usually it is not a manufacturing defect. Cracks starting at an edge or
      around a fixing point are normally caused during installation. Ask for
      photos of the full panel and the crack origin before any claim is raised.
    keywords: [crack, chipped edge, installation damage, claim]
    confirmed_by: ZL
    confirmed_at: 2026-02-11
    source_ticket: T-2025-014
    tags: [after_sales]
```

**约束**

| # | 约束 |
|---|---|
| E1 | `answer_en` 必须以 `Usually` / `In our experience` / `Typically` 开头（对应 `EXPERIENCE_PREFIX`） |
| E2 | 必须带 `confirmed_by` 与 `confirmed_at`，回答时显示 |
| E3 | 不得出现具体价格数字（价格只来自报价表） |
| E4 | 条目须覆盖 5 个意图：`spec` / `config` / `selection` / `after_sales` / `logistics` |
| E5 | 与 `standards.yaml` 冲突时，标准优先（校验：不得出现"必须合规"类结论） |

### 5.4 `capability.csv`（能力矩阵，30 行）

| 列 | 类型 | 说明 |
|---|---|---|
| `process` | enum | `annealed` / `toughened` / `laminated` / `igu` |
| `shape` | enum | `flat` / `bent`（异形） |
| `thickness_mm` | number | 见 §6.1；夹胶为公称厚度 |
| `max_width_mm` | int | 最大宽度 |
| `max_height_mm` | int | 最大高度 |
| `max_area_m2` | number | 最大面积 |
| `min_width_mm` | int | 最小宽度 |
| `min_height_mm` | int | 最小高度 |
| `tolerance_mm` | number | 尺寸公差 |
| `min_radius_mm` | int | 异形最小弯曲半径；`flat` 为 0 |
| `igu_cavity_mm` | varchar | 仅 `igu` 行，如 `6/9/12/16` |
| `notes` | text | 备注 |

**唯一键：`(process, thickness_mm, shape)`。** 30 行构成：

| 分组 | 行数 | 说明 |
|---|---|---|
| `toughened` / `flat` | 8 | 8 个整数厚度 |
| `toughened` / `bent` | 6 | 异形，带最小弯曲半径 |
| `annealed` / `flat` | 6 | 原片，按进货板幅 |
| `laminated` / `flat` | 4 | 4 个公称厚度 |
| `igu` / `flat` | 6 | 玻璃厚度，腔体见 `igu_cavity_mm` |

**先定尺寸与价格的唯一事实来源**：`capability.csv` 是所有"能不能做"的判据，报价表与交期表只能引用它允许的厚度。

### 5.5 `pricing.csv`（报价表，20 行）

| 列 | 类型 | 说明 |
|---|---|---|
| `process` | enum | 同 5.4 |
| `thickness_mm` | number | **必须存在于 capability** |
| `coating` | enum | `none` / `low_e_soft` / `low_e_hard` / `tinted` |
| `unit_price_aud_m2` | number | 含 GST |
| `min_charge_aud` | number | 最小收费（小面积时生效） |
| `moq_m2` | number | 最小起订面积 |
| `valid_from` / `valid_to` | date | 报价有效期 |
| `cost_price_aud_m2` | number | **内部成本，永不返回给前端**（验证脱敏） |

### 5.6 `leadtime.csv`（交期表，10 行）

| 列 | 类型 | 说明 |
|---|---|---|
| `process` | enum | 同 5.4 |
| `thickness_max_mm` | number | 该档覆盖的厚度上限 |
| `qty_max` | int | 该档覆盖的数量上限 |
| `business_days` | int | 标准交期 |
| `rush_available` | bool | 是否可加急 |
| `rush_surcharge_pct` | number | 加急费比例 |
| `note` | text | 如 `imported stock: add 8-10 weeks` |

### 5.7 `tickets.jsonl`（历史工单，30 条）

```json
{"ticket_id":"T-2025-001","channel":"phone","intent":"spec","query":"Can you do 12mm toughened 2400 by 3000?","answer_given":"Yes, within furnace limit. 15 business days.","outcome":"quoted","escalated":false,"date":"2025-03-04"}
```

| 字段 | 说明 |
|---|---|
| `channel` | `phone` / `email` |
| `intent` | 必须来自 `Intent` 枚举 |
| `escalated` | 是否转工程师（用来算"转接次数"基线） |
| `outcome` | `quoted` / `lost` / `info_only` / `claim` |

**用途**：算经验覆盖率基线（P2 / M6 指标）、badcase 素材。**其中 20 条不进入评测集**，只做统计。

## 6. 数字自洽规则（本规格最重要的一节）

语料内部矛盾会让评测结果变成噪音。以下五条必须由 `scripts/build_corpus.py` **断言检查**，不通过就不生成。

### 6.1 厚度枚举唯一（按工艺区分）

```
# 原片 / 钢化 / 中空用整数厚度
INT_THICKNESS_MM = {4, 5, 6, 8, 10, 12, 15, 19}

# 夹胶用公称厚度（玻璃+胶层+玻璃），不能表示成整数
LAMINATED_NOMINAL_MM = {6.38, 8.76, 10.76, 12.76}

# 中空腔体
IGU_CAVITY_MM = {6, 9, 12, 16}

# 各工艺允许的厚度集合
ALLOWED = {
  "annealed":  {4, 5, 6, 8, 10, 12},
  "toughened": {4, 5, 6, 8, 10, 12, 15, 19},
  "laminated": {6.38, 8.76, 10.76, 12.76},
  "igu":       {4, 5, 6, 8, 10, 12},
}
```

出现在：能力矩阵、手册参数表、报价表、槽位校验、意图样例。**任何地方出现 `7mm` / `9mm` / 夹胶写成 `8mm` 即报错。**

### 6.2 能力矩阵是上限的唯一来源

- 手册里的"max panel size"必须 ≤ 能力矩阵对应行
- 报价表只能出现能力矩阵中存在 `(process, thickness)` 组合
- 交期表的分档必须覆盖报价表全部组合

### 6.3 尺寸样例必须落在允许域内

除**刻意为负面样例**的条目（需标注 `expect: reject`），所有举例尺寸必须满足：

```
min_width ≤ width ≤ max_width
min_height ≤ height ≤ max_height
width × height / 1e6 ≤ max_area_m2
```

### 6.4 价格与交期不得出现在经验与标准语料里

- 经验条目、标准摘要中出现 `$` 或 `days` 需人工复核
- 价格只来自 `pricing.csv`，交期只来自 `leadtime.csv`

### 6.5 时间线自洽

- 手册 `revision` 与 `effective_from` 一致
- 报价 `valid_from ≤ valid_to`
- 工单日期早于"系统上线"（设定为 `2026-01-01`）

## 7. 渲染规格

### 7.1 XLSX（3 个）

| 要求 | 说明 |
|---|---|
| 单 sheet，名称 `data` | 多 sheet 会让解析器选错 |
| 第 1 行表头，第 2 行起数据 | 不合并单元格，不加标题行 |
| 单位写在表头里 | `Thickness (mm)`，不写在单元格里 |
| 冻结首行 | 便于人工核对 |
| 列宽自适应 | 便于人工核对与汇报 |

### 7.2 DOCX（1 个）

| 要求 | 说明 |
|---|---|
| 标题层级用 Heading 1/2/3 | 验证解析器能否还原层级 |
| 表格用真实 Word 表格 | 验证"表格是否被拍平" |
| 警告用独立段落 + 加粗前缀 | `DANGER:` / `WARNING:` / `CAUTION:` |
| 页码 | 用于验证出处引用 |

### 7.3 PDF（3 个）

| 文件 | 生成方式 | 目的 |
|---|---|---|
| `tempering.pdf` | DOCX → PDF（LibreOffice），文本可选 | 测文本型 PDF 解析 |
| `iglazing.pdf` | reportlab 直接排版，长句 + 深层级编号 | 测条款式文档 |
| `tempering_scan.pdf` | 上述 PDF → 转图片 → 重新打包为纯图片 PDF | 测 OCR 路径 |

### 7.4 MD（9 个）

- 8 个标准摘要：`standards/as1288.md` 等，每条一个二级标题
- 1 个战地手册：`experience/fieldbook.md`，每条 `## EXP-00x` + Q/A

### 7.5 JSONL（1 个）

`tickets/tickets.jsonl`，一行一条，UTF-8，无 BOM。

## 8. ground truth 与评测集派生

### 8.1 ground truth 存在哪

不单独维护"标准答案文件"，而是**从 seeds 派生**：

| 问题类型 | ground truth 来源 |
|---|---|
| 尺寸/能力类 | `capability.csv` 对应行的判定结果 |
| 价格类 | `pricing.csv` 对应行的 `unit_price_aud_m2` |
| 交期类 | `leadtime.csv` 对应行 |
| 合规类 | `standards.yaml` 的 `answer_en` |
| 售后/经验类 | `experience.yaml` 的 `answer_en` |
| 手册类 | `manual_*.yaml` 对应段落/表格行 |

### 8.2 评测集构成（120 条，`scripts/build_eval.py` 生成）

| 类别 | 条数 | 来源 |
|---|---|---|
| 尺寸与能力（`spec`） | 30 | capability + 手册参数表 |
| 配置（`config`） | 15 | 手册 + 经验 |
| 场景选型（`selection`） | 20 | standards |
| 售后（`after_sales`） | 25 | experience + tickets |
| 交期物流（`logistics`） | 15 | leadtime |
| 兜底（`other`） | 5 | 闲聊/无关 |
| **负面样例（应拒答/追问）** | 10 | 超限尺寸、缺槽位、无依据问题 |

**要求**

| # | 要求 |
|---|---|
| V1 | 每条的 `ground_truth` 能绑定到具体 `chunk_id` |
| V2 | 问题用**客户口吻**（含口语、缩写、拼写错误），不用书面语 |
| V3 | 负面样例必须明确标注 `expected_state`（`escalate` / `need_slot`） |
| V4 | 同一知识点最多出 2 条不同问法，避免评测被单一知识点主导 |
| V5 | 30 条工单中有 20 条**不进**评测集，留作统计 |

## 9. 合成数据的真实性边界（必须遵守）

这是**演示用合成语料**，不是任何真实企业的文档。为避免误导与实际错误，规定：

| # | 规定 |
|---|---|
| B1 | 标准号与标题真实，但**摘要文字是本项目撰写的**，`section` 只写节标题/节号，**不编造具体条款号** |
| B2 | 每份标准摘要文件头部必须写明：`Synthetic summary for demonstration. Not the standard text.` |
| B3 | 所有尺寸、价格、交期数字是**合成的**，不来自任何真实企业 |
| B4 | 答案模板必须带限定语：`subject to site measurement and NCC/DA requirements` |
