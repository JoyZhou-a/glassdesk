# 项目 A（旧项目）：玻璃企业英文客服知识助手

> 定位：简历中的「过去项目」——证明能交付、懂业务。
> 技术血统：黑马 `Itcast_qa_system` 的工程化 + 玻璃业务改造。
> 作用：为项目 B 提供**可对比的基线指标**。

---

## 1. 一句话定义

给客服与销售一个快捷键唤起的助手，**把"打电话问工程师、再自己翻译"这条链路，换成"30 秒内拿到可直接使用的英文答案 + 出处"**。

---

## 2. 业务背景与角色

设备来自中国与德国，**两者都提供官方英文文档**。所以"语言"不是文档层面的问题，而是**人际链路**的问题。

| 角色 | 语言能力 | 说明 |
|---|---|---|
| 客户 | 纯英文 | 电话 / 邮件，等待时间短，随时可能转向竞争对手 |
| 客服 | **中英双语** | 电话中作答，被问参数时需现场求证 |
| 销售 | **纯英文本地人士** | 报价、选型、邮件与 WhatsApp |
| 工程师 | 中文，**英文无法电话交流** | 唯一掌握判例与经验的人 |

> **输出形态按渠道分，不按角色分**：客服和销售都会用电话和邮件。电话 → 电话模式；邮件/WhatsApp → 邮件模式。

**现状链路（一次问题 = 2 次人际交接 + 1 次现场翻译）：**

```
英文客户 ──→ 双语客服 ──→ 中文工程师 ──→ 中文解释 ──→ 客服现场翻译 ──→ 英文客户
                ↑              ↑              ↑            ↑
            查不到参数      被打断一次      口语化/不完整   术语可能翻错
```

**目标链路：**

```
英文客户 ──→ 客服 / 销售 ──→ 系统（英文文档 + 能力表 + 经验库）──→ 英文客户
```

> 系统替代的不是"翻译"，是**"工程师的英文替身"**。

---

## 3. 核心痛点与指标

### 3.1 四个痛点

| # | 痛点 | 现状 | 指标（目标值待实测） |
|---|---|---|---|
| P1 | **培训周期长** | 新人要背一本"客服手册"才能独立接电话，约 __ 周 | 达到独立接听所需周数；FCR 首次联系解决率 |
| P2 | **工程师被打断** | 每天被叫走 __ 次；每次中断后需 __ 分钟回到状态（炉温曲线要重看） | 每日转接次数；连续工作时长 |
| P3 | **客户等待** | 电话中等待或"回头打给你"；邮件更慢 | 首字延迟 P95；30 秒内给出答案的比例 |
| P4 | **客户流失** | 等待期间接触竞争对手 | 转接订单的流失率（估算） |

### 3.2 真正的瓶颈（不是语言）

| 瓶颈 | 具体表现 | 系统能否解决 |
|---|---|---|
| 定位 | 知道答案在 AS 1288 里，30 秒内翻不到第几条 | ✅ 检索 |
| 跨源综合 | 一个答案要拼三份资料：能力矩阵 + 标准 + 交期 | ✅ 多路合并 |
| 转述 | 条款语言 → 客户听得懂的话 | ✅ 生成约束 |
| **经验判断** | "这客户的情况到底行不行"——文档里没写，只在工程师脑子里 | ⚠️ 只能靠**经验库** |

### 3.3 能力边界（必须写进产品说明）

> **文档与经验库里有的，系统必须接管；两处都没有的（现场判断、客户特例），系统必须立刻转人工，不许多猜一句。**

转接率不追到 0，而是**可解释地下降**：剩下的部分是系统主动识别出"必须问人"的。

## 4. 范围

### In Scope

1. 英文语料解析与入库（PDF / DOCX / Excel）
2. 混合检索 + 父块还原 + 重排
3. **双输出模式**：电话模式（口语、可念）/ 邮件模式（结构化、可复制、可附报价）
4. **来源分级**：权威 / 经验，答话术不同
5. 强制引用 + 检索不到时拒答并转人工
6. 意图识别 + **结构化槽位**双路（叠加开关，非二选一）
7. 结构化通道：能力矩阵 / 报价 / 交期
8. **经验沉淀闭环**：答不了 → 一键建条目 → 工程师中文口述 → LLM 转英文 → 入库
9. FAQ 快路径（BM25 精确匹配，0 次 LLM 调用）
10. 前端：客服悬浮窗 + 销售面板 + 极简管理页
11. 评测：120 条测试集 + 六项指标

### Out of Scope（明确不做）

1. **不做图片 / 多媒体答案** —— 电话场景是纯文本消费；因此不引入 MinIO，不建图片表
2. 不做多租户、不做自助注册
3. 不做富文本渲染
4. 不做实时语音转写（只处理手动输入的文本）
5. 不做在线下单（只答"能不能做 / 多久 / 价格区间"）
6. **不做跨语言检索** —— 语料本身是英文，不引入中文资料

## 5. 知识源与来源分级

| 知识源 | 形态 | 权威级 | 用途 |
|---|---|---|---|
| 设备手册（中国设备） | PDF，清单/参数表式 | 权威 | 工艺、参数、故障 |
| 设备手册（德国设备） | PDF，长句/条款式，层级深 | 权威 | 工艺、参数、故障 |
| 澳洲标准摘要 | 条款号 + 英文结论 | 权威 | 合规判定 |
| 能力矩阵 | Excel → DB | 权威 | 尺寸 / 厚度 / 异形 / 中空上限 |
| 报价与交期 | Excel → DB | 权威（**禁模型生成**） | 价格、交期 |
| **客服战地手册** | 文本，Q&A 式，生产经验总结 | **经验** | 常见问题"实际是怎么回事" |
| 历史工单 | 结构化 + 文本 | 经验 | 判例、badcase |
| 工程师口述沉淀 | 增量条目（中文口述 → 英文入库） | 经验 | 闭环增长 |

**分级的作用**：
- 权威 → 可直接对客户说，且必须带出处
- 经验 → 可以说，但话术要带"通常 / 我们一般"，并显示确认日期

## 7. 架构

```
客服 / 销售输入
        │
        ▼
FastAPI /api/chat（WebSocket 流式）
        │
   ① 闲聊/问候 → 模板话术（不调模型）
        │
   ② FAQ 快路径：BM25 精确匹配 ≥ 阈值 → 直接返回（0 次 LLM）
        │  未命中
   ③ 意图识别（英文 BERT 多分类）
        │
        ├─ 槽位抽取（正则优先 + LLM 兜底 + 白名单校验）
        │      → need_structured = true/false（**叠加开关**）
        │
        ├─ 结构化通道（need_structured = true）
        │      → MySQL 查能力矩阵 / 报价 / 交期
        │      → 模板填充（模型无权生成数字）
        │      → 三态：可做 / 缺槽位追问 / 超限+给上限
        │
        └─ 文档通道（始终执行）
               → 改写（可选 HyDE）
               → hybrid（dense + sparse）
               → 父块还原 → rerank
               → 带 authority + 出处 top-k
        │
   ④ 合并两路结果（rerank 统一排序）
        │
   ⑤ 生成（双模式）
        ├ 电话模式：结论 → ≤3 条补充 → 出处；口语、≤60 字/句、禁表格
        └ 邮件模式：结构化、可复制、带出处、可附报价与交期
        │
   ⑥ 落库：会话、路由路径、命中 chunk、延迟（用于评测与 badcase 归因）
```

### 7.1 意图类别（5 类 + 兜底）

刻意只保留最具代表性的 5 类，不做穷举——这是"真实项目"的选择，也降低标注成本。

| 类别 | 覆盖的客户问题 | 主要通道 |
|---|---|---|
| `spec` | 尺寸 / 厚度 / 异形 / 最大加工范围 | 结构化 + 文档 |
| `config` | 中空 / 三玻 / Low-E / 特殊编码 | 结构化 + 文档 |
| `selection` | 泳池围栏 / 门 / 天窗该用什么 | 文档（合规） |
| `after_sales` | 裂纹 / 起雾 / 划痕 / 理赔 | 文档（经验为主） |
| `logistics` | 交期 / 运费 / 加急 / 分批 | 结构化 |
| `other` | 闲聊、打招呼、与业务无关 | 模板话术或转人工 |

> `need_structured` 是**独立于意图的叠加开关**：即使意图是 `selection`，只要抽到尺寸槽位，仍然要查能力矩阵。

## 8. 实现流程

### S1｜骨架与规约
- 工程骨架、`CLAUDE.md`、`docs/`、配置（相对路径 + 环境变量）、日志双输出、pytest 空跑
- 验收：pytest 全绿；`/health` 200；无硬编码路径

### S2｜语料构建（代表性样本，不求周全）

模拟"一年前的项目"应有的规模：够撑起完整闭环，又能逐条核对。

| # | 语料 | 规模 | 备注 |
|---|---|---|---|
| 1 | 能力矩阵 Excel | 30 行 | 厚度 × 工艺 × 尺寸上限 × 公差 |
| 2 | 报价表 + 交期表 Excel | 20 行 + 10 行 | 含 GST、MOQ、加急费 |
| 3 | **客服战地手册** | 40 条 Q&A | 经验条目，带日期与确认人 |
| 4 | 设备手册节选 | 1 份，约 25 页 | 中资风格：清单 + 2 个参数表 + 3 个警告框 |
| 5 | 澳洲标准摘要 | 8 条 | AS 1288 / AS 2208 / AS 4666 / AS 1926.1 各 2 条，只写条款号 + 英文结论 |
| 6 | 历史工单 | 30 条 | 脱敏，供经验类检索与 badcase |

- 合计约 130 条知识单元
- 要求：与向量库无关的纯文件格式（JSONL + Excel），供项目 B 复用
- 验收：每条答案都能在语料中找到原文；有 ground truth

### S3｜入库管线（分源切分）
- 中国手册 → 按表格行 + 清单项切，表头随行
- 德国手册 → 按编号层级切，chunk 带完整路径（如 `4.2.1.3`）
- 标准 → 整条条款切，不切断
- 经验条目 → 按 Q&A 单元切
- 英文递归切分器；统一编码 bge-m3 → Milvus
- 验收：给定问题能定位到文档 + 页码 + 条款号

### S4｜检索
- hybrid（WeightedRanker）+ 父块还原 + rerank + 过滤（authority / 文档类型）
- 验收：带出处的 top5；Recall@5 基线

### S5｜生成（双模式）
- 电话模式 / 邮件模式两套 prompt；来源分级话术；强制引用；拒答
- 验收：电话模式可念、带出处；邮件模式可整段复制

### S6｜意图 + 结构化槽位
- 英文 BERT 多分类 + 槽位 schema + 校验三态
- 验收：尺寸/价格类问题，数字 100% 来自表；缺槽位必追问，不猜

### S7｜经验沉淀闭环
- 答不了 → 一键建"待确认条目" → 工程师中文口述 → LLM 转英文 → 客服确认 → 入库（experience / 日期 / 确认人）
- 验收：同一条问题第二次出现时能自动回答；经验覆盖率可统计

### S8｜前端 + 评测
- 三视图：悬浮窗（电话模式）、销售/邮件面板（邮件模式）、管理页
- 评测：120 条测试集 → Recall@5 / 答案正确率 / 幻觉率 / 首字延迟 P95 / 30 秒答复率 / 经验覆盖率
- 验收：数字写进 README

## 9. 已确定的决策

| 编号 | 决策 | 理由 |
|---|---|---|
| D1 | 不做图片链路，不引入 MinIO | 电话场景纯文本；图是负资产（带宽/延迟/诱导"见下图"） |
| D2 | 语料全英文，**不做跨语言检索** | 设备方都提供官方英文文档；语言瓶颈在人际链路，不在文档 |
| D3 | 新增**结构化槽位通道** | 一半答案在 Excel 里，纯 RAG 必然编数字 |
| D4 | 路由用 **`need_structured` 叠加开关**，不是二选一 | 混合问题（尺寸+隔音）单选必丢一半 |
| D5 | **来源分级**：权威 / 经验 | 客服要敢用；合规答案必须可追溯；经验答案不能冒充规范 |
| D6 | 保留 Redis，用途收窄为答案缓存 | 教学项目里 Redis 存的"全量分词表"本质是启动预热，应放进程内存 |
| D7 | 检索策略砍到 2 种（直接 + HyDE） | 延迟敏感；删功能本身是取舍证据 |
| D8 | 意图模型换 `distilbert-base-uncased` | 语料与 query 全英文，`bert-base-chinese` 不可用 |
| D9 | **双输出模式**（电话 / 邮件） | 一个照着念，一个复制进邮件；按渠道分，不按角色分 |
| D10 | **工程师经验入库**，并建沉淀闭环 | "减少打扰"从一次性变递减的唯一途径 |
| D11 | 语料用模拟数据 + 可复现生成脚本 | 不能带前公司数据；自造语料才有 ground truth |
| D12 | 切分策略**按文档来源路由** | 中资清单式与德资条款式结构差异极大 |
| D13 | 报价用字段级脱敏 | `cost_price` 永不返回，只返回含 GST 的售价 |
| D14 | 从第一天采集**命中日志 + 基线指标** | 没有基线，B 的"提升"无法证明 |

## 10. 结构化槽位（slot schema 雏形）

| 槽位 | 类型 | 取值 / 校验 | 对应表字段 |
|---|---|---|---|
| `quantity` | int | ≥1 | 报价表 |
| `thickness_mm` | float | {4,5,6,8,10,12,15,19} | 能力矩阵 + 报价 |
| `width_mm` | float | >0，≤ 炉膛上限 | 能力矩阵 |
| `height_mm` | float | >0，≤ 炉膛上限 | 能力矩阵 |
| `area_m2` | float | 由宽高计算 | 能力矩阵（面积上限） |
| `process` | enum | annealed / toughened / laminated / igu | 能力矩阵 |
| `shape` | enum | rectangular / arched / circular / trapezoid | 能力矩阵（异形） |
| `radius_mm` | float | 异形时必填，≥ 最小弯曲半径 | 能力矩阵 |
| `igu_config` | string | 如 `6-12-6` / `6-12-6 Low-E argon` | 能力矩阵 |
| `application` | enum | pool_fence / door / ceiling / shower / balustrade / shopfront / window | 合规规则表 |
| `location` | enum | ACT / NSW / VIC / ... | 交期表（运费/时效） |

**校验三态**：全通过 → 答；缺槽位 → 追问；超限 → 说不行 + 给上限 + 替代方案。

## 11. 已知技术陷阱（来自对教学项目的代码审查）

| 问题 | 影响 | 处理 |
|---|---|---|
| BM25 用 softmax 后取 0.85 阈值 | 语料越多分数越平，阈值漂移 | 用 rerank 判重或原始分归一化 |
| 英文无词干化 | `toughened` / `tempered` 视为两词 | 英文同义词表做查询扩展 |
| 表格逐单元格拍平 | 二维关系丢失 | 表格结构化解析，单独入库 |
| 检索为空仍让 LLM 硬答 | 幻觉 | 空或低分 → 拒答 |
| 超长截断从尾部截 | 模板里问题在末尾，会被切掉 | 先保证问题完整 |
| 流式输出不带出处 | 无法追溯 | 返回结构体带 source/page/clause/authority |
