## 1. 背景

工厂设备来自中国与德国，**两家都提供官方英文文档**。因此问题不在文档语言，而在**知识在人与人之间的传递方式**。

目前一次客户咨询的实际链路是：

```
英文客户 → 双语客服 → 中文工程师 → 中文解释 → 客服现场翻译 → 英文客户
```

一次问题包含 **2 次人际交接 + 1 次现场翻译**。工程师正盯炉温曲线，被叫走后需要时间重新进入状态；客服在电话里等，客户也在等；等不及的客户会去问下一家。

---

## 2. 用户与角色

| 角色 | 语言能力 | 使用场景 | 关键约束 |
|---|---|---|---|
| 客户 | 纯英文 | 电话 / 邮件询价与咨询 | 不愿等 |
| 客服 | 中英双语 | 通电话中作答 | 手不离电话，只能瞄屏幕 |
| 销售 | 纯英文本地人士 | 报价、选型、邮件与 WhatsApp | 需要能整段复制的内容 |
| 工程师 | 中文，英文无法电话交流 | 被问到时口述一句结论 | 不愿意被打断 |
| 主管 | — | 看命中率与 badcase | 偶尔查看 |

> 客服与销售**都使用电话和邮件两种渠道**。输出形态由**渠道**决定，不由角色决定。

---

## 3. 现状（As-Is）

| # | 现状 | 后果 |
|---|---|---|
| A1 | 被问具体参数时必须致电工程师 | 客服等待、工程师中断 |
| A2 | 客服拿到中文解释后自己翻译 | 术语翻错、信息丢一半 |
| A3 | 新客服要背一本《客服手册》才能独立接听 | 培训周期约数月 |
| A4 | 手册 500 页 + 标准 + 能力表 + 报价表分散在四处 | 电话中 30 秒内翻不到 |
| A5 | 一个答案常要拼三份出处 | 拼不出来就干脆问人 |
| A6 | 邮件回复慢 | 客户被竞争对手抢走 |

---

## 4. 产品目标

> **把"打电话问工程师、再自己翻译"这条链路，换成"30 秒内拿到可直接使用的英文答案 + 出处"。**

产品替代的对象不是"翻译"，而是**"工程师的英文替身"**。

### 4.1 四个目标（对应四个痛点）

| # | 痛点 | 目标 | 衡量方式 |
|---|---|---|---|
| P1 | 培训周期长 | 把"背手册"变成"查系统" | 新人可独立接听所需周数（对比口径见 §5） |
| P2 | 工程师被打断 | 转接次数下降，且剩余转接**可解释** | 每日转接次数；转接原因分布 |
| P3 | 客户等待 | 电话中 30 秒内给出可用答案 | 首字延迟 P95；30 秒答复率 |
| P4 | 客户流失 | 减少"我回头打给你" | 转接订单占比（估算口径） |

### 4.2 能力边界（产品级承诺，写进界面文案）

> **知识库中有的，系统必须接管；知识库中没有的（现场判断、客户特例），系统必须立刻转人工，不许多猜一句。**

转接率不追求降到 0，而是**可解释地下降**：下降的部分是系统接管的，剩下的部分是系统**主动识别**出必须问人的。

---

## 5. 成功指标

| # | 指标 | 口径 | 目标值 |
|---|---|---|---|
| M1 | 首字延迟 P95 | 从提交问题到首个 token 到达 | < 1.5 s（电话模式） |
| M2 | 30 秒答复率 | 30 s 内给出完整可用答案的请求占比 | ≥ 90% |
| M3 | 答案正确率 | 120 条测试集中，结论与 ground truth 一致的比例 | ≥ 85% |
| M4 | 幻觉率 | 出现"知识库中不存在的事实/数字/条款"的答案占比 | ≤ 3% |
| M5 | Recall@5 | 正确出处出现在 top5 中的比例 | ≥ 90% |
| M6 | 经验覆盖率 | 历史工单中，系统可独立回答（无需转人工）的比例 | 基线 → 迭代后 +__% |
| M7 | 每日转接次数 | 日志中 `escalate` 触发次数 / 工作日 | 基线 → 下降 __% |

> 目标值中"基线 / 下降 __%"部分在 S8 评测后回填。**禁止在未实测时填写。**

## 6. 用户故事与验收条件

### US-01 电话中查最大尺寸（结构化通道）

- **角色/渠道**：客服 / 电话
- **输入**：`Can you make 12mm toughened glass, 2400 wide by 3000 high?`
- **系统行为**：抽槽 → 校验 → 查能力矩阵 → 电话模式作答
- **验收条件**：
  1. 抽取到 `thickness_mm=12`、`width_mm=2400`、`height_mm=3000`、`process=toughened`
  2. 数字**全部**来自能力矩阵，模型不得生成任何尺寸
  3. 首行是可念的一句话结论（≤ 20 词）
  4. 全长 ≤ 3 行，无表格、无 Markdown 标题
  5. 末尾带出处 `(Capability Matrix, row __)`

### US-02 电话中查交期与价格

- **角色/渠道**：客服 / 电话
- **输入**：`How long for 2 sheets of that? And price?`
- **验收条件**：
  1. 能沿用上一轮槽位（`quantity=2` 可补，`thickness/process` 继承）
  2. 价格含 GST 并显式标注 `incl. GST`
  3. `cost_price` 字段**永不出现在响应中**（字段级脱敏）
  4. 交期给出区间而非单点

### US-03 邮件中的合规配置建议（文档通道）

- **角色/渠道**：销售 / 邮件
- **输入**：`What glass do we need for a pool fence in ACT?`
- **验收条件**：
  1. 命中泳池围栏相关条款，引用原文条款号（如 `AS 1926.1`）
  2. 输出为可整段复制的段落，含 `Applicable standard` 与 `Recommended configuration`
  3. 不得给出"绝对合规"结论，必须写明 `subject to site measurement and NCC/DA requirements`
  4. 附一条 `Experience:` 条目（若经验库有）并标注日期

### US-04 售后：裂纹成因

- **角色/渠道**：客服 / 电话
- **输入**：`The glass has cracks after installation. Is it a defect?`
- **验收条件**：
  1. 优先检索经验库（`after_sales` 意图）
  2. 给出**最多 3 个**最可能成因，按可能性排序
  3. 明确区分"制造缺陷 / 运输 / 安装"三类责任
  4. 触发 `need_human=true`（理赔类必须转人工），并给出转接话术

### US-05 槽位缺失时必须追问

- **输入**：`Can you make a big one?`
- **验收条件**：
  1. **不猜**尺寸，不调用 LLM 生成答案
  2. 追问只问缺失的槽位，一次问完（`What size and thickness?`）
  3. 响应中标记 `state = need_slot`

### US-06 经验沉淀闭环

- **角色**：客服 → 工程师 → 客服
- **流程**：系统答不了 → 客服一键建"待确认条目" → 工程师中文口述 → LLM 转英文标准表述 → 客服确认 → 入库（`authority=experience`，带日期与确认人）
- **验收条件**：
  1. 条目入库后，同一问题第二次出现时能自动回答
  2. 回答带 `Experience, confirmed YYYY-MM-DD` 前缀
  3. 经验条目可被下架（`status=archived`），下架后不再被检索到

## 7. 产品形态与交互原则

### 7.1 三个视图

| 视图 | 使用者 | 形态 |
|---|---|---|
| 悬浮窗（电话模式） | 客服 | 定宽 420px，快捷键唤起，Esc 关闭 |
| 邮件面板（邮件模式） | 销售 / 客服 | 侧栏，答案可整段复制，可附报价与交期 |
| 管理页 | 你 / 主管 | 语料上传、chunk 预览、经验条目审核、badcase 列表 |

### 7.2 交互硬规则

| # | 规则 | 理由 |
|---|---|---|
| I1 | 快捷键唤起 → 输入 → 答案出现 → Esc 消失，全程不切换页面 | 电话中不能导航 |
| I2 | 电话模式正文**最多 3 行**，超出折叠 | 一只手要拿电话 |
| I3 | 出处固定显示在末尾，格式 `(文档名, 页码, 条款号)` | 客户追问时可念 |
| I4 | 电话模式**禁止**表格、Markdown 标题、图号引用 | 念不出来 |
| I5 | 单句 ≤ 60 字符 | 一口气能读完 |
| I6 | 低置信度（< 阈值）必须显式提示 `Low confidence — consider checking with engineering` | 决定客服敢不敢用 |
| I7 | 答案标注权威级别：`Standard/Manual` 或 `Experience` | 前者可对客户说，后者要说"通常" |

### 7.3 状态与错误态

| 状态 | 界面表现 |
|---|---|
| `ok` | 正常答案 + 出处 |
| `need_slot` | 追问缺失槽位 |
| `low_confidence` | 答案 + 黄色提示 |
| `escalate` | 拒答 + 转接话术 + 一键建经验条目 |
| `service_error`（模型/检索不可用） | 明确报错 + 建议走人工，**不得静默返回空答案** |

## 8. 知识源与权威分级

| 知识源 | 形态 | 权威级 | 用途 |
|---|---|---|---|
| 能力矩阵 | 表 | 权威 | 尺寸 / 厚度 / 异形 / 中空上限 |
| 报价与交期 | 表 | 权威（禁模型生成） | 价格、交期 |
| 设备手册（节选） | PDF/DOCX | 权威 | 工艺、参数、故障 |
| 澳洲标准摘要 | 条款号 + 英文结论 | 权威 | 合规判定 |
| 客服战地手册 | Q&A 文本 | **经验** | 常见问题"实际是怎么回事" |
| 历史工单 | 结构化 + 文本 | 经验 | 判例 |
| 工程师口述沉淀 | 增量条目 | 经验 | 闭环增长 |

**分级规则**：

- `authority=standard` 或 `manual` → 可直接对客户说，必须带出处
- `authority=experience` → 必须带"通常 / 我们一般"话术，并显示确认日期
- 两类冲突时，**权威优先**，经验作为补充

## 9. 范围

### In Scope

1. 英文语料解析与入库（PDF / DOCX / Excel）
2. 混合检索 + 父块还原 + 重排
3. 电话模式 / 邮件模式两套输出
4. 权威 / 经验分级与话术
5. 强制引用 + 运行时拒答
6. 意图识别（5 类 + 兜底）+ 结构化槽位抽取
7. 结构化通道：能力矩阵 / 报价 / 交期
8. 经验沉淀闭环
9. FAQ 快路径（0 次 LLM 调用）
10. 三个前端视图
11. 120 条测试集 + 7 项指标

### Out of Scope（明确不做）

| # | 不做 | 原因 |
|---|---|---|
| O1 | 图片 / 多媒体答案 | 电话场景是纯文本消费；不引入 MinIO，不建图片表 |
| O2 | 跨语言检索 | 语料全英文，语言瓶颈在人际链路 |
| O3 | 多租户 / 自助注册 | 内部工具，账号即权限 |
| O4 | 富文本渲染 | 与 I4 冲突 |
| O5 | 实时语音转写 | 只处理手动输入的文本 |
| O6 | 在线下单 | 只答"能不能做 / 多久 / 价格区间" |
| O7 | 自动报价单生成（PDF） | 邮件模式只给可复制的文字，不做排版 |

## 10. 关键假设与风险

| # | 假设 / 风险 | 若不成立的影响 | 应对 |
|---|---|---|---|
| R1 | 官方英文文档覆盖了 80% 的客户问题 | 系统价值大幅下降 | 用经验库补；并在评测中量化覆盖率 |
| R2 | 客户问题可被 5 类意图覆盖 | 分类错误导致误路由 | `other` 兜底 + 低置信度转人工 |
| R3 | 尺寸/价格类问题可被槽位正则覆盖 | 抽不到槽位 → 无法查表 | LLM 兜底 + 追问 |
| R4 | 工程师愿意口述经验 | 沉淀闭环不成立 | 一键建条目、口述一句话即可，降低摩擦 |
| R5 | 模拟语料与真实业务分布接近 | 评测数字无意义 | 明确标注"模拟数据"，不包装成真实生产数据 |
| R6 | 业务指标（转接次数、流失率）无真实日志 | 无法声称业务收益 | 只用日志可测的指标；其余标注为"估算口径" |

## 11. 术语表

| 术语 | 含义 |
|---|---|
| 槽位（slot） | 从自然语言中抽出、可校验、可落到数据库字段的参数 |
| 权威级（authority） | `standard` / `manual`（权威）与 `experience`（经验） |
| 电话模式 | 口语化、可朗读、≤3 行、禁表格的输出 |
| 邮件模式 | 结构化、可整段复制、可附报价交期的输出 |
| `need_structured` | 独立于意图的布尔开关：本次问题是否含可计算参数 |
| 经验覆盖率 | 历史工单中系统可独立回答的比例 |
| 炉膛上限 | 钢化炉可加工的最大玻璃尺寸，能力矩阵的核心字段 |
